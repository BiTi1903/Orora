# Rà bảo mật và triển khai Storage — 17/11/2026

## Storage rules

`storage.rules` giữ quyền đọc công khai đã có, nhưng chỉ cho admin upload, ghi đè, sửa metadata hoặc xóa. Admin được nhận diện như Firestore: custom claim boolean `admin:true` hoặc document `adminUsers/{uid}.enabled:true` ở database `(default)`. Không thay đổi `firestore.rules` hay tự cấp quyền cho tài khoản.

Upload/update chỉ nhận file không rỗng, tối đa 10 MiB, MIME JPEG/PNG/WebP/GIF/AVIF. Không cho SVG/HTML hoặc đổi metadata ảnh thành HTML. Delete là quyền riêng để không phụ thuộc `request.resource` của upload. Rules chỉ kiểm tra metadata, không thể xác thực nội dung byte hay quét ảnh.

Admin hiện tải ảnh bằng Cloudinary (`src/lib/cloudinary.js`), không phải Firebase Storage. Upload thành công qua ImageField không chứng minh Storage rules đã có hiệu lực. Không thay đổi cấu hình Cloudinary hoặc ảnh hiện có.

## Kiểm tra local/CI

Cần Node 22 và Java 21:

```sh
npm ci
npm run test:rules
```

Lệnh chỉ khởi động Firestore/Storage Emulator với project **demo-orora-security**, chạy các ca từ chối user thường/anonymous/chưa đăng nhập, admin claim và admin document, giới hạn ảnh, public read, delete và ngăn tự cấp quyền. `firebase.emulators.json` là cấu hình kiểm tra, không liên kết project production. CI có job `storage-rules` riêng.

Nếu máy dùng HTTP proxy, Firebase CLI có thể gửi cả REST request localhost qua proxy dù đã đặt NO_PROXY. Khi emulator báo admin document không được phép nhưng custom claim vẫn được phép, kiểm tra kết nối localhost. Trong môi trường làm việc này, tạm bỏ HTTP_PROXY/HTTPS_PROXY (cả dạng chữ thường) chỉ cho tiến trình emulator đã giải quyết lỗi đó. Không cần nới rules.

## Triển khai production: chưa thực hiện

Repo chỉ có `.env.example`, không có `.firebaserc` hoặc phiên Firebase production được xác minh. Đã thử `npm run deploy:storage -- --non-interactive` cho đúng project, nhưng Firebase CLI dừng ở `Failed to authenticate, have you run firebase login?`. Workspace không có phiên Firebase CLI, FIREBASE_TOKEN hoặc ADC được cấu hình. Rules chưa được publish; chưa upload/xóa ảnh thật hoặc kiểm tra Firebase Console.

Project production được chủ website xác nhận: **ororavn-e6b49**. Sau khi đăng nhập Firebase bằng tài khoản có quyền (dùng `npx firebase login` trên máy của bạn, không gửi token/mật khẩu qua chat):

```sh
npm run deploy:storage
```

`firebase.storage.json` chỉ khai báo Storage rules; script dùng `--only storage --project ororavn-e6b49`, không triển khai Firestore rules. Khi rules dùng `firestore.get/exists`, Firebase cần quyền truy cập Firestore cho Storage service; kiểm tra bước cấp quyền/IAM của Firebase trong quá trình triển khai. Giữ bản rules đang dùng để có thể rollback.

Sau triển khai, dùng Firebase Storage SDK hoặc Rules Playground để kiểm tra: admin hợp lệ upload/đọc/xóa ảnh test; user thường và anonymous bị từ chối; file quá giới hạn hoặc HTML bị từ chối. Dùng thư mục thử riêng và xóa ảnh thử sau khi kiểm tra. Cloudinary không thuộc bước kiểm tra này.

## Thư viện runtime

Đã chạy `npm audit fix` không dùng `--force`, cập nhật lockfile trong phạm vi phiên bản cho phép. Audit runtime trước khi sửa: **15 cảnh báo (4 high, 11 moderate)**; sau sửa: **12 (4 high, 8 moderate)**. Các cảnh báo chưa được xử lý triệt để.

`@grpc/grpc-js` cũ nằm trong Firebase Firestore SDK; `uuid` cũ đi theo các thư viện Google của Firebase Admin. `npm audit fix` thông thường chưa loại bỏ được toàn bộ chuỗi phụ thuộc. Không ép override `uuid` sang major mới, không tự nâng Firebase SDK sang major mới hoặc khẳng định các cảnh báo không thể bị khai thác. Cần đợt nâng SDK có kiểm tra tương thích/auth/Firestore và triển khai thử riêng.

Đối chiếu lại bằng `npm audit --omit=dev`; số cảnh báo có thể thay đổi theo advisory của registry. Firebase CLI và rules-unit-testing là devDependencies phục vụ emulator, không được import vào website hoặc API production.
